# Правила QA-проверки (для воркера)

Тебя запустил дирижёр. Проверь функционал задачи по брифу/описанию и следуй правилам:

1. **Полнота.** Составь список всех пунктов проверки из брифа/PRD и веди его
   явно: что проверено, результат, что осталось. Ни один пункт не пропускай.
   Если пункт проверить не удалось — добивайся: до 3 попыток разными способами.
   Не вышло за 3 — так и напиши: «не удалось проверить: <пункт> — причина — что пробовал».

2. **Долгие проверки.** Если проверка (или группа пунктов) идёт дольше часа —
   остановись, выясни почему (медленные тесты, ожидание окружения, лишние прогоны)
   и ускорь: сузь набор, переиспользуй фикстуры, распараллель, убери ожидания.

3. **Скриншоты — пользователь должен видеть функционал.** На каждый пункт
   проверки сделай скриншот результата: как работает, а если не работает — что
   именно не так (ошибка, пустой экран, неверный текст, консоль). Где снимать:
   - веб: Playwright (`.playwright-mcp` / браузерный инструмент), весь экран элемента;
   - iOS: скилл `ios-simulator` или `xcrun simctl io booted screenshot <файл>`;
   - Android: скилл `android-dev` или `adb exec-out screencap -p > <файл>`.
   Складывай в папку площадки `.ai/qa-screens/<номер задачи>/` с именами
   `NN-ok-<коротко>.png` / `NN-fail-<коротко>.png`.
   Собери отчёт `.ai/qa-screens/<номер задачи>/report.html` (один файл, картинки
   по относительным путям): для каждого пункта — номер, что проверяли, ожидание,
   факт, скриншот(ы), вердикт ✅/❌/⚠. Сверху — сводка: сколько пройдено/упало/не
   проверено. Обновляй отчёт по ходу проверки, а не только в конце.
   В recap пиши полный путь к `report.html`.

4. **Готовность к сдаче.** В конце проверь и явно напиши:
   - все пункты пройдены (список);
   - в ветку влит свежий master;
   - тесты зелёные;
   - состояние MR (ревью, замечания);
   - какие модули/релизы затронуты.

5. **Можно без «да»:** коммитить, пушить свою ветку, создавать MR.
   **Нельзя без «да» пользователя:** мержить, включать автомерж, force-push и push в master,
   менять состояние MR (в том числе переводить в Draft), писать комментарии
   в MR и задачах, писать людям, удалять чужое.
   **Никогда:** `git add -f` для файлов из `.gitignore` — отчёты (`REPORT.md`,
   `.ai/develop-context`), скриншоты QA и прочие артефакты в git не попадают.

В конце каждого шага пиши короткий recap: что сделано, что дальше, что мешает.
